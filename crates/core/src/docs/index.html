Examples示例

# Official OpenAI SDKs and most tools read these. No code change needed.
export OPENAI_BASE_URL={{ORIGIN}}/v1
export OPENAI_API_KEY=sk-...   # your own key
from openai import OpenAI

client = OpenAI(base_url="{{ORIGIN}}/v1")  # api_key from OPENAI_API_KEY

r = client.responses.create(model="gpt-4.1-mini", input="Hello")
print(r.output_text)

c = client.chat.completions.create(
    model="gpt-4.1-mini",
    messages=[{"role": "user", "content": "Hello"}],
    stream=True,
)
for chunk in c:
    print(chunk.choices[0].delta.content or "", end="")
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "{{ORIGIN}}/v1" }); // apiKey from OPENAI_API_KEY

const r = await client.responses.create({ model: "gpt-4.1-mini", input: "Hello" });
console.log(r.output_text);

const e = await client.embeddings.create({ model: "text-embedding-3-small", input: "Hello" });
console.log(e.data[0].embedding.length);
# Streaming Responses API (-N disables curl's buffering)
curl -N {{ORIGIN}}/v1/responses \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4.1-mini","input":"Say hello","stream":true}'

# Chat Completions
curl {{ORIGIN}}/v1/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4.1-mini","messages":[{"role":"user","content":"Hello"}]}'
# Decisions API: questions in, probabilities out
curl {{ORIGIN}}/v1/decisions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-6-luna","input":"The mug arrived cracked, I want my money back",
       "questions":[{"type":"predicate","name":"refund_requested",
                     "instructions":"Does the customer ask for a refund?"}]}'
# → {"answers":[{"type":"predicate","name":"refund_requested","probability":1.0}], ...}

For AI agents给 AI Agent

Paste this into an agent's instructions, or point it at {{ORIGIN}}/llms.txt (plain text, same content).把下面这段放进 Agent 的指令里，或者让它读取 {{ORIGIN}}/llms.txt（纯文本，内容相同）。

Use the OpenAI API through {{ORIGIN}}/v1 instead of https://api.openai.com/v1.
- Set the OpenAI base URL to {{ORIGIN}}/v1 (or env OPENAI_BASE_URL). Change nothing else.
- Authenticate with the user's own key: header "Authorization: Bearer $OPENAI_API_KEY".
- Request and response bodies are identical to the OpenAI API; streaming (SSE) works.
- Supported: every /v1/* HTTP endpoint (chat/completions, responses, embeddings, decisions, models, ...).
  Not supported: WebSocket / Realtime.
- Errors with OpenAI's JSON shape come from OpenAI; a 401/404 saying "Bearer" or "/v1/*" comes from this proxy.
- Full reference: {{ORIGIN}}/llms.txt

Troubleshooting常见问题

You see现象Meaning and fix原因与处理
404 Use /v1/* for API requestsBase URL is missing /v1, or the client added a second /v1.Base URL 少了 /v1，或客户端又拼了一次 /v1。
401 … Authorization: Bearer <key>No key was sent. A 401 in OpenAI's own wording means the key itself is wrong.没有带 Key。若 401 是 OpenAI 的原文提示，说明 Key 本身不对。
403 unsupported_country_region_territoryFrom OpenAI: the caller's location is not a supported region.来自 OpenAI：调用者所在地不在支持地区。
Streaming arrives all at once流式结果一次性到达Something between you and this endpoint buffers responses. With curl, add -N.中间某层在缓冲响应；curl 请加 -N。
501 unsupported_transportWebSocket / Realtime was attempted. Use the HTTP endpoints.尝试了 WebSocket / Realtime，请改用 HTTP 接口。

Good to know须知

  • Requests are billed to the API key you send. This endpoint stores no keys.费用记在你发送的 API Key 上，本服务不保存任何 Key。
  • Rill keeps no response cache and no request or body logs. The host's own infrastructure may log traffic; use an endpoint you trust.Rill 不缓存响应，不记录请求和正文；托管平台可能有自己的日志，请使用你信任的地址。
  • Rill does not change who may use the API. Follow OpenAI's usage policies.Rill 不改变 API 的使用资格，请遵守 OpenAI 的使用政策。
  • Health check: /health (checks this proxy, not OpenAI).健康检查：/health（检查本代理，不代表 OpenAI 状态）。
